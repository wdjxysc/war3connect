# War3 Connect 0.3.0

C# / .NET 8 实现的 Windows / Linux 魔兽争霸 III 经典 TFT 1.27 联机平台内测版。

公开仓库不包含实际服务器地址。请在客户端填写管理员提供的 HTTPS 地址，或使用本机开发服务。0.3.0 的原生地图流程需要同步更新服务端和客户端；部署说明见 [通用部署指南](docs/DEPLOYMENT.md)。

当前实现已通过模拟游戏的自动化联机测试。尚未用两台运行真实 War3 1.27 的电脑完成对局验收，因此不应将此版本视为已经验证兼容的正式对战平台。平台不包含游戏程序或地图。

## 已实现

- Avalonia 跨平台中文客户端：注册、登录、大厅、创建/加入/退出房间、成员列表、文字聊天、游戏路径选择、窗口模式启动。
- 检查 `war3.exe` 文件版本，同一房间要求完整版本号一致，隔离 1.27a / 1.27b。
- 平台不选择、读取或校验地图；房主在 War3 内选图建主机，其他玩家在原生局域网列表中加入，由游戏处理缺失地图下载及校验。该原生下载流程仍待真实游戏验收。
- W3GS TFT 1.27 局域网发现、玩家本地游戏公告、动态本地 TCP 代理端口。
- 每名玩家独立 WebSocket 中继连接，房主和玩家均主动连接公网服务器，无需房主做路由器端口映射。
- 账号密码 PBKDF2-SHA256 加盐存储；12 小时会话、房间密码、成员鉴权、单账号单会话、请求限流、中继限流与超时清理。
- 房间成员 45 秒心跳超时清理；建图公告 8 秒过期；未配对中继 15 秒过期。游戏开始后公告过期不会关闭已有对战连接。

首版使用账号 JSON 文件和内存房间，便于单机直接运行；未接入 PostgreSQL/Redis。房间/聊天状态通过 HTTP 轮询同步，游戏数据使用独立二进制 WebSocket，未引入 SignalR。服务端和联机代理使用 .NET 自带组件；桌面界面使用 Avalonia NuGet 包。

## 开发环境与启动

开发需要 Windows 10/11 或 Linux、.NET 8 SDK；首次构建需联网下载 Avalonia NuGet 依赖。服务端可运行于安装 ASP.NET Core 8 Runtime 的 Windows 或 Linux。

在项目根目录的 PowerShell 中执行：

```powershell
./scripts/build.ps1 -Test
```

测试会启动自己的临时服务器，使用回环网络和 UDP 6112；运行测试时请关闭本机 War3，避免占用此端口。测试账号和日志写入 `artifacts/tests/<运行编号>/`，不会修改开发账号文件。

分别启动服务端和客户端：

```powershell
./scripts/start-server.ps1
./scripts/start-client.ps1
```

本地服务端默认监听 `http://127.0.0.1:5080`，测试本地服务时请在客户端填写此地址。客户端首次启动默认地址为 `http://127.0.0.1:5080`；连接远程服务器时自行填写 HTTPS 地址。首次使用点击“注册”即可注册并登录；账号数据保存在根目录 `data/accounts.json`。客户端只保存服务器、用户名、游戏路径、Wine 设置，不保存密码或会话令牌，设置位于 `%LOCALAPPDATA%/War3Connect/settings.json`。

脚本仅在程序尚未构建时自动编译。修改代码后请重新运行构建脚本。

## 客户端服务器地址配置

客户端程序旁的 `clientsettings.json` 用于设置默认地址，构建和发布时自动复制：

```json
{
  "ServerUrl": "http://127.0.0.1:5080"
}
```

- 界面中修改地址后点击 **保存地址**，无需登录即可保存。下次启动优先使用该用户保存的地址。
- **使用默认** 会重新读取程序旁的 `clientsettings.json`，并将其中地址保存为当前用户设置。修改默认配置后，已有用户可点击此按钮切换。
- 读取优先级：有效的用户设置 → 程序旁默认配置 → 内置本机开发地址。配置不存在或损坏时会回退；损坏或无效配置的原因显示在连接日志中。
- 支持完整 HTTPS 根地址和自定义端口，例如 `https://example.com:8443`；本地开发/SSH 隧道允许 `http://127.0.0.1:5080` 或 `http://127.0.0.1:15080`。
- 公网 HTTP、账号密码嵌入地址、URL 子路径/查询参数不被接受。登录后地址锁定，切换服务器需先退出账号。

## 发布包

```powershell
./scripts/package.ps1
```

输出：

- `artifacts/release/War3Connect-client-win-x64-0.3.0.zip`：解压后运行 `War3Connect.Client.exe`，已包含 .NET 运行时。
- `artifacts/release/War3Connect-client-linux-x64-0.3.0.tar.gz`：Linux x64 客户端，使用方法见 [Linux 客户端](docs/LINUX-CLIENT.md)。
- `artifacts/release/War3Connect-server-0.3.0.zip`：解压后执行 `dotnet War3Connect.Server.dll`，需要 ASP.NET Core 8 Runtime。

客户端发布包是包含 .NET 运行时的便携版；未包含 Wine、游戏、安装器、自动更新或代码签名。服务端包仍需 ASP.NET Core 8 Runtime。服务端发布时关闭平台专用 apphost，可在兼容的 Windows/Linux .NET 运行时使用同一 DLL。

## 两台电脑如何联机

1. 准备相同完整版本的经典 TFT 1.27。房主安装要玩的地图；其他玩家无需在平台选择或预装同一地图。
2. 启动公共服务端，两台电脑的客户端填写同一个 HTTPS 地址，注册不同账号。点击“注册”会同时登录。`127.0.0.1` 仅用于服务器就在本机的开发测试，不能作为另一台电脑的服务器地址。
3. 各自选择安装目录下的 `war3.exe`。客户端仅支持 TFT 游戏发现；进入游戏后应切换到冰封王座。
4. 房主创建平台房间。其他人选中房间并加入；右侧密码框用于设置/输入房间密码，公开房间留空。
5. 房主启动 War3，在“选项 → 游戏性”将游戏端口设为 `6112`，然后进入“局域网”，在游戏内选择地图创建主机。
6. 房主平台日志应出现“发现游戏”。其他玩家在 War3 的“局域网”中等待约 2～4 秒，选择出现的游戏并加入。
7. 缺少地图的玩家在游戏内等待地图下载，房主需允许下载。由 War3 处理传输、保存和校验；所有人就绪后，房主点击开始。平台成员数量和代理连接数量不代表游戏内槽位数量。
8. 对战结束后可重新建图。房主退出平台房间或关闭客户端会关闭房间和中继连接；对战期间请保持客户端运行。

同一台电脑运行多个真实 War3 实例不在本版支持范围内。代理仅向本机回环地址发布公告，不向整个物理局域网暴露房间。

## 公网服务器配置

远程客户端强制使用 HTTPS/WSS；仅回环地址允许 HTTP/WS。请准备域名、证书和公网服务器。最简单的部署方式是在同一台服务器上运行 ASP.NET 服务和 Caddy：

```text
玩家客户端 → HTTPS/WSS 443 → Caddy → 127.0.0.1:5080 → 平台和中继
```

`deploy/Caddyfile.example` 提供反向代理示例，将域名改为自己的域名。Caddy 需独立安装配置；本项目没有自动部署或开通公网端口。保持后端仅监听回环地址。默认只信任回环代理的转发头，不能将任意公网来源设置为可信代理。

服务端启动示例：

```powershell
dotnet War3Connect.Server.dll --urls http://127.0.0.1:5080 --DataDirectory ./data
```

也提供 `deploy/Dockerfile`，从仓库根目录构建。容器内使用非 root 用户，持久化目录 `/app/data` 必须允许该用户写入。容器方案尚未在本机执行验证。

服务器必须支持长时间 WebSocket 连接。不要将 `/relay/` 当作普通短连接接口设置很短的超时。账号 JSON 文件仅支持单服务实例写入，部署时备份 `data/`；服务器重启会结束当前房间和对局连接。

## 联机实现

```text
玩家 War3 ←本地 TCP→ 玩家代理 ←WSS→ 公网中继 ←WSS→ 房主代理 ←本地 TCP→ 房主 War3
```

- 房主向本机 UDP 6112 发送 `W3GS_SEARCHGAME (0x2F)`，读取 `W3GS_GAMEINFO (0x30)`。
- 验证 TFT 产品标识与协议版本 27，解析地图路径，保留原始 host counter、entry key、地图编码数据。
- 玩家只改写公告尾部 TCP 端口，将其指向本地回环 TCP 监听器，每 2 秒重新发布公告；离开时发送 `W3GS_DECREATEGAME (0x33)`。
- 玩家游戏建立本地 TCP 连接后，服务端创建只允许该玩家和房主使用的中继。房主轮询待接入连接并连接本地实际游戏端口。
- 中继只转发有序字节，不执行游戏模拟，不推断胜负。不同玩家使用不同连接，不共享单一有序数据流。
- 中继上限 1000 条连接、每条连接每方向每 1 秒窗口最多转发 2 MiB，达到限额后等待，避免地图下载触发断线；账号最多 10000、房间最多 200、每房间最多 12 个平台成员（界面默认 8）。这些是保护上限，不是经过负载测试的容量承诺。

协议参考：[WC3LanGame 协议笔记](https://github.com/Qyperion/WC3LanGame/blob/master/Docs/Warcraft%20III%20Game%20Packet%20Specs.md)、[GProxy 游戏公告编码](https://github.com/mycard/gproxy/blob/master/gproxy/gameprotocol.cpp)。本项目独立实现协议处理，没有引入这些仓库的源码依赖。

## 首版边界

- 尚未经过真实 War3 1.27a/1.27b 的跨网络对局验证。模拟测试能验证协议处理和网络链路，不能证明游戏引擎兼容性。
- 不支持重制版、RoC 游戏发现、自动游戏内建图/加入、房主迁移、天梯、胜负结算、观战、反作弊或游戏内断线重连。
- 原生地图下载和游戏内聊天仍待实机验证；平台目前只透明转发房主与各玩家之间的 TCP 字节流，不实现游戏协议中的玩家间直连或主机迁移。
- 大厅与聊天约 2～5 秒更新。当前没有好友系统、找回密码、管理后台、多节点选择、P2P 打洞或容灾。
- 平台控制连接断开超过 45 秒会移除成员并关闭其游戏连接；会话 12 小时到期后需重新登录。

## 常见问题

- **看不到游戏**：确认是 TFT 1.27、房主已经在局域网建图、游戏端口为 6112，且日志显示“发现游戏”。检查双方是否在同一个平台房间，以及防火墙是否允许 War3 和客户端通信。
- **版本不一致**：核对完整文件版本号，不要只看“1.27”。
- **缺少地图**：在 War3 原生主机列表中加入，等待游戏内下载；确认房主允许下载、游戏目录可写。平台不再通过地图预检查阻止加入。
- **连接后掉线**：查看客户端日志和服务端的中继连接日志；检查网络稳定性、反向代理超时、房主是否退出平台房间。首版不支持掉线恢复。
- **服务器不可达**：远程地址必须为可访问且证书有效的 HTTPS 地址；不要在其他电脑使用 `127.0.0.1`。
- **登录过期**：先退出账号再重新登录；同一账号在另一处登录会使之前会话失效。
