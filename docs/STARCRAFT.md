# 星际争霸：母巢之战 1.16.1 — 第一阶段

当前只提供游戏识别、启动和平台准备房间，**尚不能通过平台跨网络对战**。

## 已实现

- 客户端选择星际后，独立保存 StarCraft.exe 路径、Wine 程序与 WINEPREFIX；原有 War3 设置自动迁移。
- 从 PE 版本资源读取完整版本号，只接受 1.16.1.x；房间成员必须使用相同完整版本。
- 星际启动不会附带 War3 的 `-window` 参数。Linux 仍通过 Wine 启动，实际游戏兼容性待验证。
- 房间以 `starcraft-bw` 标识，与 `war3-tft` 隔离，最多 8 名平台成员。
- 准备房间提供成员、聊天、心跳和清理；不发布 War3 公告、不建立 War3 TCP 代理。
- 协议版本升级为 3，客户端与服务端需同步升级；没有自动更新远程部署。

## 验证范围

自动测试覆盖合成 PE 资源版本识别、启动参数、跨游戏隔离、人数限制、HTTP 房间与聊天、准备房间代理状态，以及原有 War3 模拟端到端转发。
这些检查不代表真实 StarCraft.exe 已启动或已完成对局。

## 下一阶段：实际游戏与网络验证

1. 提供合法安装的 StarCraft.exe 路径并确认母巢之战数据完整。
2. 两台 Windows 设备以相同 1.16.1 完整版本验证 Multiplayer → LAN (UDP) 的原生发现、入房和开局；增加第三名玩家确认玩家之间的通信。
3. 验证房间虚拟网络的广播发现与双向数据传输，再选定集成方案。仅提供虚拟 IP 不能保证游戏列表可见。
4. 接入隧道认证、房间隔离、退出清理和诊断信息；验证地图传输、完整对局、丢包和断线表现。
5. 在 Windows 验收后验证 Linux/Wine。

参考：[StarCraft Over VPN 作者说明](https://s-softs.com/Projects/SoV/index.html)记录了星际 UDP 广播发现跨 VPN 的问题。它只用于方案研究，本项目未引入其源码、旧版驱动或二进制文件。
